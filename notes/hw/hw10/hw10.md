# Virtual Memory Primitives for User Programs

## Virtural memory primitives

1. Trap: handle page-fault in user mode
2. PROT1: decrease the accessibility of a page
3. PROTN: decrease the accessibility of N pages
4. UNPROTN: increase the accessibility of a page
5. DIRTY: return a list of dirtied page since the previous call
6. MAP2: map the same physical page at two different virtual addresses. at different levels of protection, in the same address space.

## Virtual memory applications

### Concurrent garbage collection

What is Concurrent garbage collection?

**Concurrent** means that the garbage collection thread can run concurrently with the mutator thread.

----

Baker's algorithm

Use vm protections to detect from-space memo references and to synchronize the collector and mutator in PAGESIZE grain.

Sets the VM protection of unscanned area's whenever the mutator tries to access an unscanned obj. page access trap, scans the obj on this page. Then unprotect page.

So, TRAP(Trap to scan), PROTN(protect to-space when flip), UNPROT(after scan unprotect page), MAP2(map same physical page to collector and mutator) are necessary.

## Vocabulary

1. Mutator: 用户工作线程
2. Collector: 收集器线程
3. 细粒度同步（Fine-grain，指针/对象级）
机制：传统的 Baker 增量算法在每次从堆中读取指针（Load）时，依靠编译器插入 1~2 条软件指令（Read Barrier）来检查该指针是否指向未复制区域。
缺陷：粒度在“单个指针”上，虽然延迟低，但每次访存都有额外指令与分支开销，全局性能损失通常达 5%~10%；若在多核上为每个对象加锁，开销更不可承受。
4. 粗粒度同步（Coarse-grain，全局 Stop-The-World）
机制：在进行垃圾回收时，将所有用户线程完全挂起，等整个堆区全部复制扫描完毕再恢复运行。
缺陷：粒度在“整个堆/整个进程”上，虽然没有日常指令开销，但单次停顿可能长达数十毫秒至数秒，无法满足低延迟、交互式系统的实时需求。
5. 中等粒度同步（Medium-grain，页级）
机制：以虚拟内存的“页（Page，例如 4KB）”为同步单元。把未扫描的内存以页为单位设为不可访问（PROTN），由 MMU 硬件自动拦截未同步页的访问（TRAP），并在处理完后以页为单位解除限制（UNPROT）
