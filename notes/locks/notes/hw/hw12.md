# Question 1

In kernel/spinlock.c, comment out or delete these lines in acquire():
```c
  while(__sync_lock_test_and_set(&lk->locked, 1) != 0)
    ;
```
and replace them with
```c
  while(*(volatile int *) &lk->locked != 0)
    ;
  lk->locked = 1;
```
Use gdb to help explore the result when you boot xv6 and run a few commands, or run usertests. You may have to boot a few times to see a problem. What goes wrong? Why?

----

Before running xv6:

The new code do not use atom instruction.
This may case more than 1 threads find `lk->locked == 0` at the same time.

`main.c` will be executed when initializing xv6.
The first place using `acquire()` is `main.c::scheduler()`.

If not fortunate, 
```c
for(p = proc; p < &proc[NPROC]; p++) {
      acquire(&p->lock);
      if(p->state == RUNNABLE) {
        // Switch to chosen process.  It is the process's job
        // to release its lock and then reacquire it
        // before jumping back to us.
        p->state = RUNNING;
        c->proc = p;
        swtch(&c->context, &p->context);

        // Process is done running for now.
        // It should have changed its p->state before coming back.
        c->proc = 0;
        found = 1;
```
More than 1 cpu swith to the same process. Then jump to `forkret()`.

If not fortunate,
```c
static int first = 1;
```
More than 1 cpu set first to 1, and `if (first)`, `fsinit()` will be executed more than once.
